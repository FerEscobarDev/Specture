# Doctor — Catalog of checks and migrations

Companion of `skills/doctor/SKILL.md`. Reference material: open it when you need to explain a
finding the script printed (its id is in the first column of its table) or to tell the user what a
pending migration id will do. You never need it to **run** the doctor — `scripts/doctor.js` is the
source of truth and prints each finding with its action.

## Contents

| Section | When you need it |
|---|---|
| Checks by release | A finding id you do not recognise — what it means and what to do |
| Migration catalog (what each id does) | `migrate` listed an id and the user asks what it changes |

## Checks by release

Checks added in v2.2.0 for the move to the convergent gate (v2.2.0 has no content migration — `migrate` only records `schema_version`):
- `gate-legacy-rejection` (WARNING) — an epic `[/]` whose last verdict for a target in its `_planning.md` is `REJECTED` over supersessions, with no `APPROVED` after it; action: re-validate under v2.2 (delta re-validation — `build` does it on resumption, those findings become `RETIRADO`).
- `claude-md-gate-overrides` (INFO) — the project's `CLAUDE.md` still carries the temporary "Spec Planning Gate — instrucciones temporales" block written for v2.1; action: remove it, v2.2.0 ships what it asked for.
- `seal-lifted` (WARNING) — the seal's `lifted_spec_paths` is not empty while an epic is `[/]`: an interrupted supersession loop left that spec editable; action: let `build` resume the loop, or re-seal with `seal-cli.js write` (check first with `seal-cli.js show`).
- `hooks-registry-missing` (ERROR, v2.9.1, Claude Code) — `hooks.enabled: true` but the installed plugin has no `hooks/hooks.json` (or it lacks the top-level `"hooks"` wrapper, or a registered script is missing): Claude Code loads a plugin's hooks only from that file or from the manifest's `hooks` key, never from the plugin's `settings.json` where v1.2.0 → v2.9.0 kept them, so every gate shipped inert. Action: update the plugin to ≥ 2.9.1, `/reload-plugins`, confirm with `/hooks` that both `PreToolUse` name `specture`.
- `hooks-self-test-failed` (WARNING) — the registry is sound but the Wait Guard, run from the project root with a known polling loop on stdin, did not deny it: the toggle or the root is what the guard does not see. Action: check `.specture/settings.yml` at the root Claude Code opens, then `/hooks`.
- `specture-script-permissions` (INFO, v2.2.1, Claude Code) — the build already ran and no settings let `seal-cli.js` run without a prompt (no `permissions.allow` rule in the project's `.claude/settings.json` / `.claude/settings.local.json` or the user settings, no `autoMode.allow` entry in `~/.claude/settings.json`); in auto mode the classifier may deny `unseal-spec` or `supersede` and every denial becomes a question to the user. Action: `hooks/README.md` § Permisos. The doctor never writes settings — the user adds the rules.

Checks added in v2.3.0 for the review stage of `build` (registers in `docs/05-specs/_reviews/`, `build/REVIEW_STAGE.md`; a project without `_reviews/` and without `**Aparcado:**` lines gets none of them):
- `review-open` (WARNING) — the current register (the last by name that is not `EJECUTADA`) is still `PREPARANDO`, `RONDA-1` or `RONDA-2`: a sitting of decisions was left halfway and the queue does not execute its epics. Action: resume with `/specture:start` — it picks up at that state without re-asking what the register already answers.
- `review-scope-drift` (WARNING) — an epic of a `CERRADA` register, neither `[x]` nor parked, whose scope fingerprint (`review.js scope-hash`: its ROADMAP block + the text of its linked RN) no longer matches the `## SCOPE` line recorded at close, or that has no SCOPE line. Each epic is judged by the last register that lists it. Action: re-review that epic before executing it — its decisions were taken over a different scope.
- `epic-parked` (INFO) — an epic `[ ]` with a `**Aparcado:**` line; the detail names the pending decision (`<clase> — <motivo>`) and its batch. Action: take it to the next review sitting; once decided, remove the line and the epic returns to the queue.
- `parked-orphan` (WARNING) — a `**Aparcado:**` line on an epic `[/]` or `[x]` (parking sets the epic back to `[ ]`), without its batch, or naming a batch with no register in `_reviews/`.
- `review-malformed` (WARNING) — a register whose parse fails (missing `ID` / `ESTADO` / `EPICS`, a malformed `A-n` / `F-n` / `PR-n` / SCOPE / APARCADOS / EJECUCIÓN line, a template marker left unfilled), or a `.md` in `_reviews/` outside the `<YYYY-MM-DD>-<slug>.md` naming, which `review.js` never reads. While the current register is malformed, `review.js status` answers `UNVERIFIABLE` and the queue stops. Action: fix it against `templates/BATCH_REVIEW_TEMPLATE.md`.

Checks added in v2.4.0 for the compliance review — the custom review rules (`.specture/review-rules.md`, opt-in — a project without the file gets none of them) and the reports in `docs/07-reviews/cumplimiento-*.md` (`review-rules-resolve.js` and `compliance.js` read the same files; `review-rules-resolve.js` refuses to run with any ERROR below, so the build and the compliance review stop on the same problems):
- `review-rules-schema` (ERROR) — a line of `## Incluye` / `## Severidades` / `## Nivel flexible` / `## Reglas` outside the grammar, a repeated `RV-n`, an unknown severity, or a glob with braces `{a,b}`. Action: fix the line against the header comment of `templates/project-config/review-rules.template.md`.
- `review-rules-include` (ERROR) — an inclusion that cannot load: a URL, an absolute path, a path outside the repository, the file itself, a missing file or heading, a heading that appears twice, or an included file with its own `## Incluye` (one level of inclusion only; it is never followed).
- `review-rules-size` (ERROR / WARNING) — one inclusion alone exceeds 60 000 characters (ERROR), or all of them together do (WARNING: a review that needs all of them fails loud). Action: include smaller sections or condition them with `cuando:`.
- `review-rules-agent-include` (WARNING) — a whole agent file (front-matter with `name`/`description`) is included: its procedure travels with its criteria. Action: include only its criteria sections (`§ <encabezado>`).
- `review-rules-glob` (WARNING, git only) — a `cuando:` or flexible-level glob that matches no tracked file, usually a typo that silently drops criteria.
- `compliance-triage-pending` (WARNING) — a milestone compliance report (`docs/07-reviews/cumplimiento-milestone-*.md`; reports of a PR or a branch are `TRIAGE: NO REQUERIDO` and never wait) still `TRIAGE: PENDIENTE`, or with findings marked `corregir` and no result under `## CORRECCIÓN`. Action: `/specture:compliance-review triage` (or let the next queue drain of `build` pick it up).
- `compliance-report-malformed` (WARNING) — a compliance report whose `STATUS` / `TRIAGE` / `Milestone` header or a finding's `Tipo` does not parse (`templates/COMPLIANCE_REPORT_TEMPLATE.md`), so `compliance.js` cannot triage or count it. Action: regenerate it with `/specture:compliance-review milestone <N>` — the report is assembled by the script, never edited by hand.
